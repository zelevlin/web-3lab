## Архитектура приложения

### Общая концепция
Веб-версия 2048 строится как модульное ООП-приложение с разделением ответственности по доменным областям: игровая логика, пользовательский интерфейс, управление состоянием, сохранение данных и взаимодействие с пользователем. Каждый модуль инкапсулирует свои данные и предоставляет понятный API для других компонентов.

### Структура модулей
1. **`core/Tile`**
   - Представляет тайл с числовым значением и состоянием (новый, объединённый, перемещающийся).
   - Отвечает за обновление значения, пометки статуса для анимаций и сброс флагов после рендера.
2. **`core/Grid`**
   - Управляет матрицей 4x4, хранилищем тайлов и их позиционированием.
   - Предоставляет методы для поиска свободных ячеек, вставки/удаления тайлов, клонирования состояния для undo.
3. **`core/GameEngine`**
   - Реализует правила 2048: смещения, слияния, расчёт очков, генерацию новых тайлов, проверку окончания игры.
   - Хранит историю ходов для отката, обеспечивает сериализацию/десериализацию состояния.
4. **`core/ScoreManager`**
   - Подсчитывает текущие очки и фиксирует максимальный результат с учётом объединений.
   - Информирует UI о изменениях счёта и возвращает данные для сохранения рекордов.
5. **`storage/StateRepository`**
   - Инкапсулирует работу с `localStorage` для состояния игры и истории ходов.
   - Предоставляет методы `loadState()`, `saveState()`, `clearState()`.
6. **`storage/LeaderboardRepository`**
   - Хранит и сортирует записи лидеров (топ-10), управляет датами и проверкой дубликатов.
7. **`ui/BoardView`**
   - Создаёт DOM-структуру игрового поля, отрисовывает тайлы, запускает анимации перемещения/слияния.
   - Взаимодействует только через методы `render(gridSnapshot)` и `updateScore(score)`.
8. **`ui/DialogManager`**
   - Управляет модальными окнами: завершение игры, форма сохранения результата, таблица лидеров.
   - Скрывает элементы управления во время показов диалогов и сообщает о действиях пользователя.
9. **`ui/ControlPanel`**
   - Отвечает за кнопку «Начать заново», «Отмена хода» и мобильный блок управления (стрелки или свайпы).
   - Делегирует события контроллеру игры и обеспечивает адаптивное отображение.
10. **`app/GameController`**
    - Связывает движок, представление, хранилище и интерфейс.
    - Обрабатывает ввод (клавиатура, тач, кнопки), обновляет состояние, инициирует сохранения и отрисовку.

### Потоки данных
1. `GameController` получает событие ввода и вызывает `GameEngine` для выполнения хода.
2. `GameEngine` изменяет `Grid`, возвращает результат (движения, слияния, очки, статус игры).
3. `ScoreManager` обновляет результат и сообщает контроллеру.
4. `GameController` передаёт снимок состояния в `BoardView`, которое минимально обновляет DOM.
5. Если игра окончена, контроллер инициирует показ модального окна через `DialogManager` и взаимодействие с `LeaderboardRepository`.
6. После каждого валидного хода `StateRepository` сохраняет текущее состояние и историю для восстановления при перезагрузке.

### Управление состоянием
- Состояние игры включает: матрицу тайлов, очки, статус (в процессе/победа/проигрыш), стек предыдущих состояний.
- Undo работает через хранение глубокой копии `Grid` и значения очков в стеке при каждом успешном ходе.
- При загрузке страницы `GameController` пытается восстановить состояние из `StateRepository`. При отсутствии данных инициирует новую игру с 1-3 случайными тайлами.

### Работа с лидербордом
- После завершения игры и сохранения имени результат добавляется в `LeaderboardRepository`, список обрезается до 10 записей.
- Диалог отображает таблицу с именем, очками и датой (формат локали пользователя).
- При успешном сохранении поле ввода скрывается, а сообщение меняется на подтверждение.

### Адаптивное поведение
- `BoardView` использует CSS-grid и параметры тайлов, чтобы поле масштабировалось от мобильной ширины до десктопа.
- `ControlPanel` переключает набор управляющих элементов: клавиатура для десктопа, кнопки/свайпы для мобильных устройств (кнопки скрываются во время модальных состояний).
- Медиа-запросы обеспечивают корректное расположение счёта, поля, панели контроля и диалогов.

### Расширяемость и переиспользование
- Ядро (модули `core`) не зависит от DOM и может покрываться тестами или переиспользоваться в других интерфейсах.
- UI-модули работают только с готовыми снимками состояния, упрощая анимации и поддержку нескольких представлений.
- Хранилища обёрнуты в классы, что позволяет заменить `localStorage` на другую реализацию без изменения остального кода.
